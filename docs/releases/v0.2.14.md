# v0.2.14

## Highlights

- `--check --probe` now reports `reconnectCleared` and `reconnectMarker`, so a skipped or failed reconnect-marker cleanup is observable.
- Both `--status` commands strictly validate the `reconnect-required` marker before reading it.
- Gitea Release publication accepts a bounded UTF-8 `--notes-file` and writes it to the Release body.

## Upgrade

- No configuration migration is required. Reconnect hosts after upgrading and use a green `--check --probe` to clear the marker.
- Existing `v0.2.13` remains immutable; publish `v0.2.14` as a separate tag and asset set.

## Added / Changed / Fixed

- Added `reconnectPending` / `clearReconnectMarker` in `src/release/install-fs.mjs`; `src/cli.mjs`, `src/release/installer.mjs` and `scripts/install-agents.mjs` share the strict marker boundary.
- Added `reconnectCleared` / `reconnectMarker` to green `--check --probe` output; in-process development calls report `no-release-root`.
- Added `loadReleaseNotes` and Release body publication for `scripts/publish-gitea-release.mjs --notes-file`.

## Verification

- `npm test`: 746 offline tests pass.
- `npm run build:release`, `npm run build:plugin`, `npm run verify:plugin`, `npm run verify:structure`, `git diff --check` pass.
- Local HTTP fixture verifies Release creation body, asset allowlist, checksums and token redaction; no live Gitea publication or host reconnection is claimed.

## Rollback

- `bash install.sh --rollback` returns to the verified `v0.2.13` release; sessions, pending state and host configuration are unchanged.
