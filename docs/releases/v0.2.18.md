# v0.2.18

## Highlights

- Concurrent sends on different aliases now queue inside the process instead of failing on the shared state lock; the same alias still keeps a single durable pending send, and only truly nested lock calls report `BUSY`.
- Native recovery rechecks the server branch at the click boundary so a held draft is never submitted into the wrong conversation.
- Release publication now rejects non-UTF-8 notes files before any network call.

## Upgrade

- Install this version with the published installer. Existing aliases, pending state and API configuration are unchanged.
- Reconnect direct hosts after installation so they load the new runtime.

## Fixed

- `ccw` / `ccw-mcp`: same-process concurrent sends on different aliases no longer fail with `BUSY`; the state lock wraps only the short `sessions.json` / `api-sessions.json` read-modify-write transactions, and completion writes re-read and merge per alias.
- `ccw ask --native`: recovery rechecks branch identity immediately before the send click; uncertain identity keeps the held draft instead of submitting.
- `publish-gitea-release.mjs --notes-file`: non-UTF-8 or oversized notes are refused before release creation.

## Verification

- `npm test`: 782 offline tests pass.
- `npm run verify:structure`: passes (122 paths / 9 strata / 34 DAG edges).
- `npm run build:release`, `npm run build:plugin`, `npm run verify:plugin`: pass.
- Live webpage verification on `claude-opus-5-5` submitted one native prompt, returned `MODEL_SEND_OK` with `complete:true`, and cleared pending (`pending:null`).
