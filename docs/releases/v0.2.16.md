# v0.2.16

## Highlights

- `--credential-helper` now actually works: the previous implementation passed an unsupported `input` option to async `execFile`, so `git credential fill` never received its query and real runs always timed out after 5s.
- Non-default Gitea ports are part of the credential query (`port=`) instead of being silently dropped.
- Reconnect-marker identity checks also compare `ctimeMs`, narrowing the stat→unlink race further.

## Upgrade

- No configuration migration is required. `v0.2.15` remains installed and immutable; upgrade to `v0.2.16` for the working credential-helper path and the marker hardening.

## Added / Changed / Fixed

- `credentialFromGitHelper` writes `protocol=https\nhost=...\n[port=...]\n\n` to the child's stdin and ends it, then parses `password=` from stdout; the token is never printed or embedded in errors.
- `reconnectPending` and `clearReconnectMarker` compare `ctimeMs` in addition to dev/ino/size/mtimeMs.
- Released together with the unhitched `warning` field and Magpie isolation test from `6d7d006`.

## Verification

- `npm test`: 750 offline tests pass.
- A real `git credential fill` subprocess resolves the operator's keychain token in milliseconds; a fake `git` on PATH verifies both the default and custom-port query shapes.
- `npm run build:release`, `npm run build:plugin`, `npm run verify:plugin`, `npm run verify:structure`, `git diff --check` pass.
- Release publication uses `--credential-helper` itself, then downloads the three assets and verifies `SHA256SUMS`; host reconnection is not claimed.

## Rollback

- `bash install.sh --rollback` returns to the verified `v0.2.15` release; sessions, pending state and host configuration are unchanged.
